# 从0搭建个人服务器：Debian + Docker + Memos + Nginx + HTTPS + 防火墙

## 前言

最近申请了一台免费的 VPS，想搭建一个属于自己的个人服务。

最初目标只是运行一个 Memos，用来记录学习笔记。

但是在实际部署过程中，逐渐理解了一个 Web 服务从上线到安全运行需要哪些组件：

- Linux服务器
- Docker容器
- 应用程序
- 数据库
- DNS解析
- Nginx反向代理
- HTTPS证书
- 防火墙

最终搭建完成：

> 一个公网可访问、HTTPS加密、经过基础安全加固的个人知识管理系统。

# 二、服务器初始化

## 1. 安装 Debian

选择 Debian 作为服务器系统。

原因：

- 稳定
- 资源占用低
- 适合长期运行服务


服务器配置：

|项目|配置|
|-|-|
|系统|Debian 13|
|CPU|1核|
|内存|1GB|
|磁盘|10GB SSD|

# 三、安装 Docker

## 为什么需要 Docker？

如果直接安装 Memos：

需要手动配置：

- 运行环境
- 依赖
- 配置文件


容易出现：

- 环境冲突
- 升级困难
- 迁移困难


Docker 提供了一种：

> 将应用和运行环境一起封装的方法。


结构：

```
Debian

↓

Docker

↓

Memos容器

↓

SQLite
```


---

## Docker中的镜像和容器

### 镜像(Image)

类似：

> 软件安装包

例如：

```
neosmemo/memos:stable
```


---

### 容器(Container)

镜像运行后的实例：

```
Memos镜像

↓

Memos容器
```


Docker负责：

- 创建容器
- 启动容器
- 停止容器
- 管理生命周期


---

# 四、部署 Memos

创建目录：

```bash
mkdir /opt/memos

cd /opt/memos
```


创建：

```bash
nano docker-compose.yml
```


配置：

```yaml
services:
  memos:
    image: neosmemo/memos:stable
    container_name: memos
    restart: unless-stopped
    ports:
      - "5230:5230"
    volumes:
      - ./data:/var/opt/memos
```


启动：

```bash
docker compose up -d
```


查看：

```bash
docker ps
```

# 五、数据持久化和迁移

## 为什么需要数据持久化？

Docker容器本身不是永久存储。

如果删除容器：

```
Memos容器
        |
        删除
```

数据可能丢失。


所以使用：

```yaml
volumes:
  - ./data:/var/opt/memos
```


表示：

宿主机：

```
/opt/memos/data
```

映射到：

容器：

```
/var/opt/memos
```


数据独立保存。


---

```
memos_prod.db
```

迁移：

```
上传

↓

VPS

↓

/opt/memos/data
```


完成后：

原来的账号和笔记继续使用。


- 端口暴露

所以增加：

Nginx。


---

## Nginx作用

Nginx是：

> Web服务器和反向代理。


结构：

```
用户

↓

Nginx

↓

Memos
```


---

## 反向代理

用户访问：

```
memo.xuruo.date
```

收到请求：


HTTP：

```

```


HTTPS：


HTTPS保护：

- 用户密码
- Cookie
- 数据内容

```
↓
```

```
↓
```

任何人可以尝试访问。


修改：

```yaml
ports:
  - "127.0.0.1:5230:5230"
```

```

↓

↓

↓
```

作用：

- 隐藏后端服务
- 减少攻击面
- 统一入口

# 十、配置防火墙 UFW

## 为什么需要防火墙？

服务器暴露在公网：

```
互联网

↓

VPS
```


任何人都可以扫描：

```
IP
端口
服务
```


攻击者可能：

- 暴力破解SSH
- 扫描漏洞
- 探测服务


防火墙作用：

> 控制哪些网络连接可以进入服务器。


---

## UFW工作原理

UFW本质上管理Linux防火墙规则。


例如：

允许：

```
22 SSH

80 HTTP

443 HTTPS
```


拒绝：

```
5230 Memos
```


---

## 配置规则

允许SSH：

```bash
ufw allow 22/tcp
```


允许网站：

```bash
ufw allow 80/tcp

ufw allow 443/tcp
```


开启：

```bash
ufw enable
```


查看：

```bash
ufw status
```


最终：

```
开放:

22   SSH
80   HTTP
443  HTTPS


关闭:

5230 Memos
```

# 十三、关于内网穿透

本质是在没有_**公网ip**_的情况下，外网设备可以访问内网.

内网穿透的核心：
> 让内网设备主动连接公网服务器，建立一条通信隧道。
