# PHP安全-TP框架

 **概念**：框架（Framework）是封装好的代码库。它将数据库操作、文件上传、路由解析等复杂底层逻辑封装成简单的方法，让开发者从“从零手写”变成“调用现成功能”，极大提高了开发效率。
 **学习目的**：主流 PHP 网站大量使用 ThinkPHP (TP) 开发。懂框架，才知道代码是如何组织的、URL 是如何访问的、漏洞是如何产生的。不懂框架，就无法进行白盒代码审计。

## TP基础构架与路由

[TP开发手册](https://www.kancloud.cn/manual/thinkphp5_1/353946)


### 1.目录结构（以 TP5 为例）
- `public/index.php`：**入口文件**。通常 Web 服务器的根目录指向这里。
- `application/`：**应用目录**。核心业务代码都在这里。
  - `config.php`：全局配置文件（如数据库账号密码）。
  - `database.php`：数据库配置。
  - `index/`：默认的模块（Module）。
    - `controller/`：控制器目录，存放业务逻辑（如 `Index.php`）。
    - `view/`：视图目录，存放 HTML 模板。
  - `route.php`：路由配置文件。


### 2. 路由访问规则 (URL)
默认的 URL 访问模式是：`模块 / 控制器 / 操作（方法） / 参数名 / 参数值`
例如：`http://域名/index.php/index/Index/test/name/xiaodi`
- `index`：模块目录名。
- `Index`：控制器文件名（`Index.php`）。
- `test`：控制器里面的方法名。
- `name/xiaodi`：传递给方法的参数（键值对）。

### 3.操作数据库

在原生态的 PHP 开发中，操作数据库需要经历“配置 -> 连接 -> 拼接 SQL -> 执行”的繁琐过程。而在 ThinkPHP 框架中，这些步骤被大大简化，并且底层自带安全防护。

----

查阅手册tp框架配置数据库，先配置application目录下的database.php文件。![image-20261025220512494](../images/image-20261025220512494.png)

![image-20261025221053899](../images/image-20261025221053899.png)

与原生态相比，框架多了过滤。

如果用户访问 `?id=1 and 1=2`，SQL 语句就会变成 `select * from news where id = 1 and 1=2`，导致 **SQL 注入漏洞**。

![image-20261025221505095](../images/image-20261025221505095.png)

修改框架代码接受参数，无论怎么修改，页面都没反应

![image-20261025221820697](../images/image-20261025221820697.png)

> **原生态写法（危险）**
>
> ```php
> $id = $_GET['id'];
> // 直接拼接变量，毫无安全性可言
> $sql = "select * from news where id = $id"; 
> $data = mysqli_query($con, $sql);
> ```
>  **框架安全写法（查询构造器）**
>```php
> // 需在顶部 use think\Db;
>$data = Db::table('news')->where('id', $id)->find();
>```

> **逻辑越权 (IDOR)**
>如果网站后台使用不同的数字（如 `adminid=1`）来区分管理员和普通用户，并且在修改用户信息时，没有在服务端校验当前用户的身份，仅凭前端传入的 `adminid` 参数决定权限，就会导致抓包修改参数实现“逻辑越权”。

### 7.代码审计思路总结

面对一个 ThinkPHP 源码，审计流程如下：

1. **信息收集（黑盒）**：查看 URL 结构、报错信息，识别是否为 TP 框架及具体版本，排查已知版本漏洞（RCE/注入）。
2. **找入口**：从 `application/` 目录下的模块开始，对应 URL 找到对应的控制器（Controller）和具体方法（Action）。
3. **找参数与危险函数**：
   - 搜索 `Db::query(`、`Db::execute(`、`$_GET`、`$_POST`，看是否有变量拼接，排查 SQL 注入。
   - 搜索 `request()->file(`，看后面有没有 `->validate()`，排查文件上传漏洞。
   - 搜索 `eval`、`system`、`file_put_contents`，排查 RCE 或任意文件写入。
4. **查配置与组件**：查看 `config.php`、`database.php`，以及 `extend` / `vendor` 目录下的第三方组件版本（如旧版 Smarty），排查第三方组件漏洞。
